# Producing a narrated image series with Studio

Turn a topic into independently watchable videos made from **still images, Ken Burns
editing and narrated audio**. Use this workflow for history, children's picture books,
science, biographies, cultural stories and other illustrated channels.

**Use Studio's own image and TTS APIs for all generated artwork and speech.** The
production service is the same Studio configured for this repository; API details
are in [api.md](api.md). The default image engine is **Qwen Image 2.1 Turbo**. Choose
an appropriate Studio speech model and voice for the audience language.

The chain is:

**Topic → episode outlines → complete script → dense image beats → character
references where needed → batch image/TTS jobs → measured audio timeline →
Ken Burns → subtitles, QC and delivery.**

These are image-sequence videos. H3/FastH3 audiovisual generation and generated
lip-sync belong to [directing-workflow.md](directing-workflow.md), a separate route.
Here, image motion is created locally during editing and narration is generated by
Studio's speech API.

## Standard execution: one JSON and one command

Use the reusable [slides_flow.py](../scripts/slides_flow.py) instead of writing new
per-video helpers. The agent authors the plan JSON and starts this same workflow:

```bash
python3 scripts/slides_flow.py path/to/plan.json
```

The workflow calls Studio for images, fixed-character edits, TTS and alignment,
renders smooth image motion on the configured Studio host, and embeds subtitles.
It resumes completed assets and keeps intermediates in `.slides-cache/`; the public
output is one MP4. Do not create contact sheets, separate previews or inspect every
image by default. Use automatic completeness/alignment/media checks, and inspect only
when the user requests it or a concrete failure needs diagnosis. Reuse the locked
series style and voice for subsequent videos.

A minimal plan has this structure:

```json
{
  "title": "A historical question",
  "language": "en",
  "voice": "Ryan",
  "image_model": "qwen-image-21-turbo",
  "style": "Classical oil-painting historical realism, natural light and earth colors.",
  "size": [1920, 1080],
  "fps": 30,
  "output": "episode.mp4",
  "subtitles": {"mode": "soft", "language": "eng"},
  "scenes": [
    {"prompt": "A specific drawable historical moment.", "narration": "The complete words spoken over this image."}
  ]
}
```

`subtitles.mode` supports `soft`, `burn` and `none`. A soft track is embedded and
selectable; burn-in remains visible in the picture. Character definitions can carry
`prompt` or an existing `image`, and a scene's `characters` lists the reference IDs
that select edit mode. Existing `image`, `audio`, `alignment`, `frames` and `clip`
inputs allow a partially completed production to be reused. Server rendering uses
`H3_DEPLOY_HOST`; local heavy rendering requires the explicit `--local` option.

To add translated subtitles, author a JSON with `language` (for example `zho`),
`title`, and `episodes`, mapping each episode ID to one translated string per scene
in plan order. Run the same command with `--translations translations.zh.json`.
An existing final MP4 is reused: the flow retains its English subtitle track, adds
Chinese as the default selectable track, and stream-copies video and audio without
regenerating assets or rendering pictures. Intermediate subtitle files stay in the
hidden cache. For a new episode, the same option generates the film first.

## 1. Confirm the brief and resume existing work

Inspect `outputs/<series-slug>/`, `PROGRESS.md`, outlines, scripts, selected artwork,
references and API job IDs before submitting anything. Reuse accepted work and
recorded settings. Do not resume a production the user previously canceled.

Record only the missing decisions; do not ask again for answers already supplied:

| Decision | Record |
| --- | --- |
| Topic | Audience, central promise, scope and intended learning/story experience |
| Episode count | The user's count; about 15 when they request a dozen or so |
| Production scope | Outlines only, one selected pilot, or the complete series |
| Narration | Language, Studio model/voice, delivery and pronunciation glossary |
| Frame | Landscape/portrait, ratio, actual output raster and fps |
| Style | Drawing/painting/rendering method, palette, texture, realism and composition |
| Captions | Languages and whether selectable, sidecar, burned in or omitted |
| Delivery | Local files, channel package, content-site edition or a channel matrix |

Guide language and narration language are separate choices. A channel can use English
narration even when planning is discussed in Chinese. Choose a voice from Studio's
actual presets and verify it with a short, reusable narration sample.

When asked to produce a film, continue through the complete selected film. Outlines,
artwork or an opening preview alone do not finish it. A request to edit this guide
alone does not start a production. Honor requested reviews without inventing
repeated approval gates.

## 2. Write the outlines before ordering artwork

An outline describes **one independent video**, not one image. Each includes:

- Stable episode ID, title, precise central question and audience value.
- Scope: period/place for history, age range for children, mechanism for science.
- Opening hook, three to six substantive beats, causal transitions and closing.
- Sources or fictional story rules, unresolved questions and research required.
- Characters/looks, settings, objects and varied visual opportunities.
- What distinguishes it from neighboring episodes and any assumed knowledge.
- An initial runtime range, revised after writing and recording the script.

Do not compress all of European history into ten disconnected summaries. Define a
coherent season premise and give every episode a bounded question. A children's
series similarly needs complete local stories, even when a cast recurs.

For a channel matrix, keep separate editorial promises and series records, with
one locked visual identity per channel/series. Reuse relevant research and assets
with attribution/version records; do not treat retitling the same film as a new
editorial concept.

## 3. Research and write a continuous script

For factual subjects, use existing knowledge to organize the topic and research the
selected episode's consequential details. Keep a claim-to-source record. Prefer
primary material and appropriate museum, archive, scholarly or institutional
sources. Check dates, names, architecture, clothes, tools and geography. Distinguish
established facts, interpretations and illustrative reconstructions.

Generated historical pictures are reconstructions, not archival evidence. A plausible
face is not an authenticated portrait. Maps, diagrams, borders and data need separate
verification; compose reliable graphics rather than trusting generated lettering.

For fiction, establish goals, story rules and emotional cause and effect. For young
children, choose suitable language and time to inspect each important illustration.

Write the entire narration as fluent prose before splitting it into images. Explain
unfamiliar concepts and connect causes to consequences. Reading the narration without
pictures must still make sense. Concatenating all beat texts must reproduce the script
exactly, with no missing sentence, duplicate line or disconnected explanation.

## 4. Lock the style and recurring identities

Decide the style **before bulk production**. Describe concrete properties:

- Painting/rendering method, degree of realism, contours and surface texture.
- Face/body proportions, apparent age, clothes, accessories and materials.
- Palette, contrast, light, environments and composition vocabulary.
- Treatment of titles, labels, diagrams and reconstruction notices.

For classical historical oil painting, for example, specify natural anatomy, layered
oil glazes, restrained brushwork, canvas texture, earth pigments and chiaroscuro,
while keeping architecture/costumes appropriate to the depicted period. Historical
painting style does not justify putting Renaissance clothes into ancient Rome.

Generate a small representative set, inspect it together, then freeze the selected
style text. Useful samples are a wide environment, an object/detail and a character
reference if the film needs one. They can be actual episode assets. Record rejected
versions and the reason; do not continue producing a rejected treatment. Repeat the
locked style wording in every prompt and maintain it across the series.
Keep the shared style block about visual treatment, not a list of scene objects: mentioning ships or people globally can make them leak into unrelated still lifes. Put content-specific props and period details only in the relevant scene prompt.

### Required generate/edit decision

1. Generate, inspect and save references for every character whose identity must
   remain recognizable. Record the exact selected look/version.
2. If a defined character appears in an image, use **edit mode with its references**.
3. If no defined character appears, use **generate mode**.
4. Anonymous background figures do not establish a recurring identity; if they become
   recognizable story roles, create references before further use.
5. New clothes, age or significant appearance changes require a new reference version
   derived from the canonical identity. Preserve older versions.

A name, repeated prose description or shared seed cannot replace a reference. Never
silently fall back to generate when a required reference is unavailable. Record the
ordered `ref_image` uploads and their roles for each request. Use the selected model's
actual reference limit from `/api/presets`; Qwen currently accepts up to four. Split
complex group compositions when necessary instead of dropping an identity reference.

For historical explainers, anonymous representative workers can illustrate a process
without inventing a named protagonist. If a recurring composite is useful, explicitly
record that the figure is illustrative, not a documented historical individual.

## 5. Plan dense, meaningful image beats

Every new picture should contribute information, evidence, a changed action state,
a relationship or an emotional development. Alternate contexts, human-scale views,
details, objects and checked diagrams. Repeated portraits plus slow zooms do not
constitute visual density.

Start with a meaningful sentence or clause per image. Roughly 2–6 seconds can be a
useful planning range, but never force all images to the same length. Maps, complex
diagrams and a child's discovery may need longer. If a passage outruns its picture,
add another meaningful image at a natural spoken boundary. If cutting is too rapid
to understand, combine beats or allow inspection time.

Record each beat's:

| Field | Purpose |
| --- | --- |
| `id` | Stable episode/image ID |
| `narration` | Exact words heard over it, not a production label |
| `visual_purpose` | The new information or story state |
| `mode` | Generate/edit, derived from visible fixed characters |
| `references` | Exact selected files/versions in upload order |
| `prompt` | Complete English still-image prompt with the locked style |
| `sources` | Supporting sources or reconstruction notes |
| `motion` | Planned focal point, zoom/pan endpoints and safe areas |
| `audio_span` | Filled later from actual narration/alignment |

Describe one drawable moment. A person noticing a seedling is a still; running,
kneeling and planting need separate images. Ken Burns changes the viewing window;
it does not animate the subject or provide lip-sync.

Edit prompts identify what each reference supplies and which background/state should
change. Check that neutral reference poses or incidental props have not leaked into
scenes. Leave framing margin for the motion endpoints and later captions. Keep
unwanted writing, logos and watermarks out of the artwork.

## 6. Submit image and narration jobs through Studio

Use the deployment configuration's `STUDIO_URL`. Inspect `/api/health` and
`/api/presets`; save the model/voice capabilities used. The examples below were checked
against this repository's forms and worker implementation on 2026-10-28.

Studio uses multipart requests and returns a job object directly. There is no extra
`data` response envelope. Read and save `id`, `seed`, status, exact request/prompt,
reference order and intended local output immediately.

### Generate a character-free image or initial reference

```bash
curl --fail-with-body -sS "$STUDIO_URL/api/jobs" \
  -F kind=image -F image_model=qwen-image-21-turbo \
  -F aspect_ratio=16:9 -F seed=42001 \
  -F 'prompt=<prompts/E001_B001.txt'
```

### Edit a scene containing a fixed character

```bash
curl --fail-with-body -sS "$STUDIO_URL/api/jobs" \
  -F kind=image -F image_model=qwen-image-21-turbo \
  -F aspect_ratio=image -F seed=42002 \
  -F 'prompt=<prompts/E001_B002.txt' \
  -F ref_image=@refs/characters/selected-look.png
```

Repeat `ref_image` for multiple references. Qwen edits require `aspect_ratio=image`
and follow the first input's canvas. Prepare landscape references when the scene
must be landscape; a portrait identity card cannot be assumed to yield a landscape
Qwen edit. A landscape reference composition can retain a clear, sufficiently large
face while matching the intended canvas.

The response mode is `t2i` without references and `i2i` with them. Image settings come
from the model registry: do not send video-only `lora`, `resolution` or `duration` as
image controls, or copy another implementation's sampler/step settings.

### Generate speech with Studio's own TTS API

Use a stable preset voice when appropriate. For English historical narration, Ryan
is one available Qwen3-TTS choice; audition and record the actual selected voice.
The `language` field for Qwen3-TTS uses the preset's language code, such as `en`.

```bash
curl --fail-with-body -sS "$STUDIO_URL/api/jobs" \
  -F kind=speech -F audio_model=qwen3_tts -F speech_mode=generate \
  -F language=en -F voice=Ryan -F seed=43001 \
  --form-string 'instruction=Calm, clear documentary narration with a warm, measured delivery and natural brief pauses.' \
  -F 'prompt=<audio/script-part-001.txt'
```

The speech response mode is `tts`; completed WAVs are downloaded through `audio_url`.
Choose from actual `speech.models`, supported modes, languages and voices returned
by `/api/presets`. Qwen3-TTS, VoxCPM2 and OmniVoice have different controls. Do not
invent arbitrary voice strings or clone inputs for ordinary preset generation.
Reference audio is used only for an explicitly selected clone mode.

Each TTS prompt is limited to 4,000 characters. Split long narration at natural
paragraphs, preserving exact text and the same voice/instruction. Do not make one
TTS request per isolated word just to obtain more pictures. A fluent recorded passage
can support many image beats in the editorial timeline. Save each original take,
its script version, model, voice, instruction, seed and measured duration.

### Batch and collect

Once the full prompts and narration are ready, submit independent image and TTS jobs
in a manageable batch to Studio's existing FIFO queue. Jobs needing references wait
for those references to finish. Prefer grouping similar model tasks to reduce
repeated image/audio model switching while preserving actual dependencies.

Poll `GET /api/jobs/<id>` about every 15 seconds in a resumable helper. Terminal states
include `done`, `failed` and `canceled`. Download `picture_url` or `audio_url` on `done`.
Returned file URLs are relative to the Studio base URL. Save files through temporary
paths before atomic rename so a partial download cannot look like a finished asset.

Never duplicate a job after an uncertain POST/poll timeout: reconcile its recorded
ID and existing history first. Record failures and retry only their causes. A job
marked done means inference finished; it does not mean the artwork or speech passed
quality control. Leave unrelated user jobs and service processes alone.

## 7. Measure narration and obtain real timing

Check that the actual speech includes every required passage, with correct names,
numbers and intelligible pronunciation. Repair a bad take locally; retain healthy
parts. Reassemble the selected takes into a continuous narration master with
normalized PCM/sample rate. Check joins for voice drift, padding, clipped phonemes
and unintended silence before choosing picture durations.

Studio TTS returns audio duration but does not provide guaranteed word-alignment
metadata. For precise image cues/subtitles, submit that **exact narration master**
to Studio's own Qwen3-ASR/Forced Aligner route:

```bash
curl --fail-with-body -sS "$STUDIO_URL/api/jobs" \
  -F kind=asr -F audio_model=qwen3_asr -F language=English \
  -F timestamps=word --form-string 'prompt=Final narration timing and review' \
  -F media=@audio/narration.master.wav
```

Collect `result.transcript` and `transcript_urls` (`json`, `words`, `srt`, `txt` where
available). Review the recognized text against script, context and audible evidence.
Correct recognition errors, not missing speech by inserting unspoken scripted words.
If essential text was omitted or hallucinated in synthesis, replace that take and
refresh the affected narration/timing.

Use aligned word/phrase spans to locate image changes. Do not fabricate word timing
by distributing characters across a known duration. Keep final subtitles tied to the
final audio master; if later editing changes speech timing, refresh alignment. The
narration master can be aligned before picture rendering because its exact audio is
then used unchanged under the assembled image sequence.

## 8. Build a timeline that follows the narration

Each image's `timeline.json` entry records its file, global start/end frames, audio
passage, actual timing source, motion endpoints and exact reference versions.

- Begin with the hook over a relevant picture, not a long silent title or fade.
- Let actions/visual discoveries accompany speech rather than adding silent waits.
- Preserve meaningful short pauses, but do not add a fixed tail to every image.
- Check neighbors as a continuous explanation/story, not as unrelated showcases.
- Default to hard cuts. If dissolves are used, account for their overlaps without
  shortening, repeating or delaying narration.

For a custom renderer, define image boundaries on a single episode clock:
`end_frame = ceil(cumulative_seconds * fps)`, with the next image starting at that
same frame. This avoids accumulating one rounded-up padding interval per picture.
Partition one narration passage among its pictures rather than copying the passage's
complete audio under every picture.

Render the picture with exact frame counts and normalize timestamps. Mux the
continuous narration once where practical. Repeated independently encoded audio
clips and stream-copy joins can expose encoder padding and drift; measure the final
file instead of trusting declared durations. Do not stretch or speed speech to fit
an arbitrary image-count/runtime target.

## 9. Apply smooth Ken Burns

Use the workflow's floating-point affine resampling with cubic interpolation. Keep
its default center-anchored small push/pull and smooth easing unless the brief asks
for more movement. Integer crop-window motion can produce micro-jitter even when
its duration and frame count are correct; increasing an oversampling factor alone
does not guarantee a stable result. Do not reintroduce the rejected zoompan draft
as the default renderer.

Keep important faces, objects and subtitle space in view at both endpoints. A
complex diagram can be held still. Rendering happens on the Studio server by
default, rather than loading the user's computer with parallel raw-frame encoding.
The whole sequence shares one narration master, so cuts do not repeat or delay audio.

## 10. Subtitles, artwork and final QC

Keep a clean master. Generate any requested subtitles from reviewed real alignment,
and mux soft subtitles without re-encoding picture/audio when that is the brief.
Burn text in only when explicitly requested. Save sidecar SRTs and correct language,
title and default-track metadata. Add intentional titles/diagram labels in a
controlled editing step rather than relying on generated spelling.

Inspect artwork at full resolution before rendering, plus motion endpoints. Sparse
contact sheets can miss unwanted writing; OCR helps but is not proof of cleanliness.
Truncated glyphs can evade OCR, so visually inspect a correction at its actual edge.

A completed episode requires:

1. All planned narration and essential visual beats are present and connected.
2. Clear consistent speech, checked names/dates and no missing/duplicate passages,
   cut-off words or unintended long silence.
3. The locked style, character identity, costume, props and correct generate/edit
   reference routing throughout.
4. Fact-checked claims, maps and reconstruction details for educational content;
   clear action/emotional continuity for fiction.
5. Smooth Ken Burns, readable composition, correct raster/ratio/fps and no unwanted
   lettering or missing media.
6. Frame count/duration matching the accepted timeline and synchronized audio and
   captions through the final sentence.
7. Caption behavior matching the brief, including hiding/switching where applicable.

Deliver film, clean master, cover, narration, requested captions, sources/credits
and publishing notes. A content-site edition can also include the transcript and
selected stills. Record checks actually performed and unresolved limitations rather
than claiming full listening or frame-by-frame review from metadata alone.

## 11. Project records, recovery and cancellation

Keep `outputs/<series-slug>/PROGRESS.md`, `series.json`, `outlines.json`, research,
style/character bibles and a versioned reference manifest. Each episode has a complete
script, image-beat plan, exact prompts, API job records, original image/audio files,
`timeline.json`, QC, subtitles, film, cover and publishing notes. Track stable IDs and
actual selected takes. Typical states are `outlined`, `researched`, `scripted`,
`style_locked`, `references_ready`, `generating`, `narrating`, `editing`, `qc`, `done`.

Retry failed jobs locally and preserve completed work. Do not rebuild a whole series
because one image or voice take is wrong. Respect the user's chosen pilot even when
other episode IDs precede it; subsequent production follows the authorized scope.

When the user stops production, stop submitting new work immediately. Cancel **owned
queued jobs first**, then the owned running job with `POST /api/jobs/<id>/cancel`, so
canceling the active job does not simply start the next queued one. Recheck recorded
IDs and `/api/health`, repeating cancellation if a dequeue race occurs. Do not cancel
unrelated projects, delete accepted local assets without a deletion request, restart
services or automatically resume canceled work. If the service becomes unreachable,
report that final verification is incomplete instead of claiming an empty queue.

Update exact next steps and delivery paths after meaningful stages. A list of
outlines, image batch or opening preview is not a finished film or finished series.
