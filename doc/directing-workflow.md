# Directing a production with MiniMax-H3 Studio: an agent workflow

This is the flow an agent (Claude Code or similar) follows to direct a multi-shot production of any genre
(animated series, drama, documentary or history explainer, talking-head presenter video, commercial, MV)
using only the H3 Studio HTTP API and ffmpeg. It grew out of a lion-themed animated series, a French
Revolution explainer, a Chernobyl documentary and a Thirty-Six Stratagems series.

The agent plays director, writer, casting, sound designer, editor and QC. The user picks or approves the
concept, reviews every batch before the next one is planned, and listens to the dialogue, which the agent
cannot hear.

## Step 0: confirm three settings with the user

Before reading further into a brief or writing anything, ask the user for these three, in one question,
with the recommended choice first. Do not assume them, even when the brief seems to imply them:

| Setting | Options | Recommended |
|---|---|---|
| Aspect ratio | 16:9 landscape, 9:16 vertical, 1:1, 4:3, 3:4 | 16:9; 9:16 for a phone talking-head video |
| Resolution | 544p, 768p | 544p: 768p is about 2× slower, and a 15 s 768p job once failed at the end with NaN audio |
| Language of dialogue and narration | Mandarin Chinese, English, other | Mandarin Chinese |

Record the answers in `00_project.md` and use them in every job (`aspect_ratio`, `resolution`) and every
voice phrase (the language at the end of each voice, `<d>[Chinese] ...</d>` or the matching language tag, and
the language named in `overall_soundscape`). The rest of this guide writes 544p, 16:9 and Mandarin as the
example; substitute the confirmed settings.

## Fixed rules

| Item | Rule |
|---|---|
| Length | Not fixed: the user's brief decides, otherwise the agent picks what the story needs |
| Resolution / aspect ratio | As confirmed in Step 0 |
| Model | Every video shot uses `fasth3-omniref` (`fasth3_omniref_8step_pruned_int8_convrot`), with or without reference images. Do not send `sampler`: OmniRef runs the official template's euler, 8 steps, and the server ignores any other choice (`fixed` in `LORAS`, `server/h3_engine.py`) |
| Shot length | 5–15 s, one continuous shot per job |
| Sound | All speech, narration, effects and score are generated by H3 inside each shot from the prompt. No other TTS, no separately mixed voice tracks |
| Language | As confirmed in Step 0 (Mandarin Chinese by default), for both dialogue and narration |
| Captions | None. No subtitles or on-screen text in any shot |
| Batches | About 2 minutes of shots per batch; each batch becomes a short preview video that the user approves before the next batch is planned |
| Files | Everything for a production goes under `outputs/<title>/` (git-ignored), named after the production's title |

Why one model for everything: a zero-reference OmniRef job is a plain text-to-video shot (the `r2v` mode
with no `ref_image`), so establishing shots and character shots come out of the same model in the same look.
The larryvrh and lightx2v routes produce a visibly different style and are not mixed in.

Throughput on the RTX 4090 at 544p (768p takes about 2×): 5 s ≈ 40 s, 10 s ≈ 70–90 s, 15 s ≈ 90–115 s. A 2-minute batch of 10 shots plus
a couple of castings takes about 20 minutes of GPU time before redos.

## Pick the genre treatment

Decide this first; it sets the style line, the cast and how sound is carried.

| Genre | Visual treatment | Voices | Shot pattern |
|---|---|---|---|
| Animated series | Stylized 3D animation, or 2D/anime if the brief asks; original characters with strong marks | Character dialogue, optional narrator | Dialogue shots with 1–3 cast members, establishing shots between scenes |
| Drama / film | Stylized cinematic 3D rather than photoreal: realistic faces are soft at 544p | Character dialogue | Like the animated series, with more close-ups and fewer characters per shot |
| Documentary / history explainer | Stylized or painterly period look; archive-like establishing shots | One off-screen narrator carries the piece; at most a line or two from a historical figure | Mostly zero-reference shots with narration; reference shots only for recurring figures |
| Talking head | One presenter, fixed set and framing, often 9:16 | The presenter speaks to camera; no narrator | Every shot uses the presenter reference and the same set phrase; cut-aways are zero-reference B-roll with the presenter's voice off-screen |
| Commercial / promo | Product hero shots, clean studio or lifestyle light | Narrator or a presenter | Short 5–10 s shots, more of them |
| MV | Shots driven by a song | The song (MiniMax Music 3 job, `kind=music`) as guide audio | Shots cut to the song's sections; pass the song slice as `audio` + `audio_start` so each shot follows it |

Use original characters, names and lines; do not reuse protected characters or dialogue from existing works.
Real historical figures are fine in explainers; keep them out of invented scandal.

## Project layout

```
outputs/<title>/
  00_project.md             confirmed settings, premise, genre treatment, style line, score line, batch plan, folder map
  01_cast_voices.md         cast bible: fixed look, keep and voice per character, narrator voice
  02_batch01_storyboard.md  storyboard of batch 1, one section per shot
  03_batch01_log.md         job ids, seeds, timings, QC verdict per shot
  04_batch02_storyboard.md  later batches continue the numbering
  prompts/                  the exact text submitted for every job
  refs/                     one cropped reference image per recurring character; refs/candidates/ for picking
  clips/                    downloaded shots; clips/casting/ holds castings, clips/rejected/ failed takes
  qc/                       contact sheets of every shot
  scripts/                  prompts.py (prompt builder), studio.py (submit/wait/download), assemble.sh, jobs.json
  batch01.mp4 ...           batch preview videos for the user
  <title>.mp4               the finished production
```

Write the docs in the user's language. Build every prompt with a script instead of typing it per job: the
script is the single source of every character's look and voice wording, which is what keeps them stable.
An earlier project's `scripts/` (for example the French Revolution explainer's) is a good starting point to copy.

## Step 1: concept, outline and batch plan

1. Write the premise, the whole story outline and the planned total length in `00_project.md`.
2. Split the outline into batches of about 2 minutes, each ending on a beat that works as a stopping point
   (a scene end, a reveal or a hook). A long piece has many batches; a 2-minute explainer is one batch.
3. Fix one **style line** (English) and append it to every prompt, ending with the no-text clause:

   > ... No text, no subtitles, no captions, no logos, no watermarks, no readable writing anywhere.

4. Fix one **score line** for the whole piece (or one per act) so the music does not jump at cuts.
5. Name every recurring location with one fixed English phrase.
6. Get the user's approval of the concept and outline before casting.

## Step 2: cast and voice bible

For every speaking or recurring role, including the narrator, fix these strings in
`01_cast_voices.md` and never paraphrase them later:

- **look** (on-screen roles): one English noun phrase with age, build, colours, costume and two or three
  distinctive marks (a scar, a notched ear, a red scarf). Distinct marks are what the model holds on to.
- **keep**: one sentence for the `retention_analysis` line ("Preserve the same ...").
- **voice**: one English phrase for gender, age, timbre, pace and attitude, ending with the language, for
  example `the calm, deep, measured voice of a middle-aged male history narrator, speaking Mandarin Chinese
  clearly at a steady documentary pace`. Write a Chinese description next to it for the user.
- **lead-in** for the narrator: `Off-screen, a narrator who is never seen says in voice-over, in <voice>:`.

Make the voices in a production clearly different from each other in gender, age or pitch, so a line is not
heard in the wrong voice. Pace the text to the shot: about 3–3.5 Chinese characters per second, so at most
~40 characters of speech in a 12 s shot and ~50 in a 15 s shot, counted across all speakers. Longer text gets
cut off at the end of the shot.

Characters that appear in a single shot, crowds and background people need no bible entry beyond a phrase in
that shot, and no reference.

## Step 3: casting (only for roles that must look the same across shots)

A role needs a reference image when it appears in more than one shot and has to be recognisable. For each,
submit a 5 s zero-reference job: the character alone, centred, fully visible (or framed as in the piece, for
example a waist-up presenter), three-quarter view, plain softly lit background in the production's style,
a slow push-in, and one line in their fixed voice. This yields the reference image and a voice test the user
can listen to. A narrator-only piece, or a piece with no recurring people, skips casting.

Pick and crop the reference frame:

```bash
# five evenly spaced frames side by side, to choose from
ffmpeg -i clips/casting/casting_ayan.mp4 -vf "select='eq(n\,6)+eq(n\,36)+eq(n\,66)+eq(n\,96)+eq(n\,120)',scale=384:-1,tile=5x1" \
  -frames:v 1 refs/candidates/ayan_sheet.jpg
# the chosen frame, cropped tightly around the character (crop=w:h:x:y in 960x544 pixels)
ffmpeg -i clips/casting/casting_ayan.mp4 -vf "select='eq(n\,66)',crop=420:504:230:40" -frames:v 1 refs/ayan.png
```

Choose a frame with the mouth closed or a neutral expression and the distinctive marks readable. The
character should fill the reference image. Cast all roles with the same style line and similar framing,
otherwise one comes out more realistic than another.

A picture job (`kind=image`, MOSS-Image) can also make a reference, for example a product, a prop or a set,
but it carries no voice test and its style may differ from the video model's; prefer a casting clip for people.

## Step 4: storyboard one batch

Write `0N_batchKK_storyboard.md` with one section per shot: length, cast (references), location, camera, the action in
timed beats, every spoken line with its speaker (or narrator), sound effects and music.

- One job is one continuous shot. Do not ask for cuts inside a job.
- At most 3 references per shot and at most 3–4 spoken lines per 15 s.
- Leave characters out of a shot's cast unless they act or speak in it.
- Mix shot lengths (5–15 s) to the pace of the scene: short shots for action and reaction, long ones for
  dialogue and narration.
- New characters introduced in a later batch get their casting job first; shots that do not need them can be
  submitted while it runs.

Real lengths snap to the 17k+5 frame grid at 24 fps: 5 s → 124 frames (5.1667 s), 10 s → 243 (10.125 s),
12 s → 294 (12.25 s), 15 s → 362 (15.0833 s). Use the real length in `summary` and clamp the last beat to it:

```python
def frames(seconds):
    n = max(5, round(seconds * 24))
    return n + (5 - n % 17) % 17
```

## Step 5: prompts

Dialogue: `<d>[Chinese] <line></d>`, introduced by `says in <voice>:` (or the narrator lead-in), so every line
carries its speaker's fixed voice. In `overall_soundscape`, name which voices are heard and that they speak
Mandarin Chinese. When nobody on screen talks, say so ("Nobody on screen speaks; crowds only murmur without
words") so the model does not invent speech.

**Zero-reference shots** use the ref2va layout without `subject_definitions` and `retention_analysis`:

```
summary:
[reference generation] In one continuous 12.2500-second shot, <one-sentence summary>

detailed_description:
Visual style: <style line>

[Shot 1, 00:00.000-00:07.000] <scene, action, camera>. Off-screen, a narrator who is never seen says in
voice-over, in <narrator voice>: <d>[Chinese] ...</d>

[Shot 1, 00:07.000-00:12.250] <action>

overall_soundscape:
<ambience, effects, voices and their language>

non_diegetic_music:
<score line>
```

**Reference shots** add the subject sections. `<Subject N>` and `<Picture N>` follow the order the
`ref_image` files are sent:

```
subject_definitions:
<Subject 1> is <look 1>, as shown in <Picture 1>.
<Subject 2> is <look 2>, as shown in <Picture 2>.

summary:
[reference generation] In one continuous 15.0833-second shot, <summary using the subject tags>

retention_analysis:
<Subject 1> (appears in [Shot 1]): fully_preserved - <keep 1>
<Subject 2> (appears in [Shot 1]): fully_preserved - <keep 2>

detailed_description:
Visual style: <style line> <optional scene lighting>

[Shot 1, 00:00.000-00:04.000] <action>

[Shot 1, 00:04.000-00:09.000] <Subject 1> turns to <Subject 2> and says in <voice 1>: <d>[Chinese] ...</d>

[Shot 1, 00:09.000-00:15.083] ...

overall_soundscape:
...

non_diegetic_music:
<score line>
```

For a talking head, every shot repeats the same set phrase and framing ("<Subject 1> sits at a light oak desk
in a bright minimal studio, waist-up, facing the camera, speaking directly to the viewer"), so cuts between
shots read as one continuous recording.

## Step 6: submit through the Studio API

`POST /api/jobs` takes a multipart form, one job per shot:

```bash
curl -s -X POST http://<host>:8190/api/jobs \
  -F "prompt=<prompts/S04.txt" -F resolution=544p -F lora=fasth3-omniref \
  -F aspect_ratio=16:9 -F duration=15 \
  -F ref_image=@refs/leizong.png -F ref_image=@refs/ayan.png
```

- `prompt=<file` makes curl read the field from the file (keeps newlines and Chinese text intact).
- Leave out `ref_image` for a zero-reference shot; `lora=fasth3-omniref` still makes it an OmniRef job.
- Leave `seed` out for a random one; the response returns it. Record id, seed, prompt file and refs for
  every job in `scripts/jobs.json`, keyed by shot name, so any shot can be reproduced.
- Submit the whole batch at once: the server runs one job at a time in FIFO order.
- Poll `GET /api/jobs/{id}` every 15 s until `done` or `failed`, then download `video_url`. Run the wait loop
  in the background and let the harness notify you instead of sleeping in the foreground.

## Step 7: QC and redo

For every shot, make a contact sheet (one frame every 2 s) and measure the audio:

```bash
ffmpeg -i clips/S04.mp4 -vf "fps=1/2,scale=320:-1,tile=8x1" -frames:v 1 qc/S04.jpg
ffmpeg -i clips/S04.mp4 -af volumedetect -vn -f null - 2>&1 | grep -E "mean_volume|max_volume"
```

Check the duration, that the cast matches the references (marks, colours, costume), that the action follows
the beats, that there is no broken anatomy and **no burned-in text**, and that the audio track is present.
Note small drifts in the log instead of redoing.

Burned-in captions are the most common failure in Chinese-dialogue shots, especially period pieces: in one
series 5 of 10 first takes had Chinese subtitles along the bottom (y ≈ 469–509), and stronger "no subtitles"
wording barely helped. Narration-only shots with nobody speaking on screen were clean. So:

- Submit dialogue-heavy shots twice from the start and keep the clean take.
- Last resort: crop the caption band and scale back (`crop=816:462:72:0,scale=960:544`).

Redo a shot by resubmitting the same prompt with a new random seed, or rewrite its beats if the model keeps
missing an action. Move failed takes to `clips/rejected/` and keep the shot name for the new job.

## Step 8: batch preview and user approval

Assemble the batch into `batchKK.mp4` (see Step 9) and stop. Report to the user: the file path, its length,
which shots were redone and why, and what to check by eye and ear (voices, pronunciation, whether lines were
cut off, drifts noted in QC). The agent cannot judge pronunciation or timbre and must say so.

Only after the user approves the batch (and any redos they ask for are done) plan the next batch's storyboard.
Carry fixes forward: if a voice phrase or a style detail did not work, change it in the bible and the prompt
builder before the next batch, and note the change in `00_project.md`.

## Step 9: assembly

Shots come out at very different loudness (about −35 to −15 dB mean). Normalise each shot, reset timestamps
so the result is constant 24 fps, pad or trim each audio track to its video length, and add tiny fades to
avoid clicks at the cuts. `scripts/assemble.sh <out.mp4> <clip>...`:

```bash
#!/usr/bin/env bash
set -euo pipefail
out=$1; shift
ins=""; fc=""; maps=""; i=0
for f in "$@"; do
  ins="$ins -i $f"
  d=$(ffprobe -v error -show_entries format=duration -of csv=p=0 "$f")
  fc="$fc[$i:v]setpts=N/24/TB,setsar=1[v$i];"
  fc="$fc[$i:a]asetpts=PTS-STARTPTS,loudnorm=I=-16:TP=-1.5:LRA=11,aresample=48000,"
  fc="${fc}apad=whole_dur=$d,atrim=0:$d,afade=t=in:d=0.05,afade=t=out:st=$(python3 -c "print($d-0.08)"):d=0.08[a$i];"
  maps="$maps[v$i][a$i]"; i=$((i+1))
done
ffmpeg -y $ins -filter_complex "${fc}${maps}concat=n=$i:v=1:a=1[v][a]" -map "[v]" -map "[a]" \
  -fps_mode cfr -r 24 -c:v libx264 -crf 16 -preset slow -pix_fmt yuv420p -c:a aac -b:a 192k \
  -movflags +faststart "$out"
```

Verify with `ffprobe -count_frames`: the frame count equals the sum of the shots, `avg_frame_rate` is exactly
24/1, and audio and video durations match. Without `setpts=N/24/TB` and `-fps_mode cfr` the concat output had
a variable frame rate and drifted 0.75 s longer than its frames.

When every batch is approved, assemble all shots in order (not the batch previews, to avoid re-encoding twice)
into `<title>.mp4` and report it the same way. Optionally upscale the finished shots through
`POST /api/jobs/{id}/upscale` before the final assembly if the user wants a higher resolution.

## Known limits

- Realistic close-up faces are soft at 544p; stylized looks hide this well.
- Characters can drift slightly within a long shot (hair or fur colour, face proportions).
- Specific physical actions (a leap from a height, catching an object) are not always followed.
- Long speech is cut off at the shot end; keep to the pacing budget above.
- The model sometimes cuts to a closer framing mid-shot by itself; usually acceptable.
